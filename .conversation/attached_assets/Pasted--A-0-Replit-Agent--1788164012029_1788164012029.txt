# 設計書A — キッチンカー在庫エージェント（最小構成）

## 0. このドキュメントの位置づけ

Replit Agent への指示書。ここに書かれた範囲**のみ**を実装する。
書かれていない機能は、良かれと思っても追加しない。

---

## 1. 何を作るか

キッチンカー店主向けの在庫管理エージェント。
店主が売上を渡すと、在庫を自動で減らし、ズレを学習して精度を上げていく。

**今回の実装範囲は Tier 1 のみ。ホットドッグ1商品。ターミナルで動く CLI。**

---

## 2. 背景：Tier 分類（実装は Tier 1 のみ、設計の前提として記載）

| | 性質 | 例 | 今回 |
|---|---|---|---|
| Tier 1 | 減る・計算で読める・回転が速い | ソーセージ、パン | **実装する** |
| Tier 2 | 減る・人と客で変わる・回転が速い | ケチャップ、トッピング | 実装しない |
| Tier 3 | 減る・計算で読める・回転が遅い | 包み紙、ガスボンベ | 実装しない |
| Tier 4 | 減らない・期日が来る | 点検、支払い、営業許可 | 実装しない |

後で Tier 2〜4 を足せるよう、品目データに `tier` フィールドだけは持たせておく。
ただし今回は値が `1` のものしか扱わない。

---

## 3. 技術要件

- **言語**: Python 3.11 以上
- **フレームワーク**: `strands-agents`（AWS製、Apache 2.0）
- **モデル**: Amazon Bedrock 経由の Claude Sonnet（Strands のデフォルト）
- **データ**: JSON ファイル1枚（`data/state.json`）。DB は使わない
- **UI**: なし。ターミナルで対話する
- **Web フレームワーク不要**。Flask / FastAPI / React は入れない

### Secrets（Replit Secrets に格納。コード直書き禁止）

```
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_DEFAULT_REGION   （値: us-west-2）
```

`.env` は作らない。`os.environ` から読む。

## 4. データ構造（`data/state.json`）

```json
{
  "products": [
    {
      "id": "hotdog",
      "name": "ホットドッグ",
      "recipe": [
        { "item_id": "sausage", "qty": 1 },
        { "item_id": "bun", "qty": 1 }
      ]
    }
  ],
  "items": [
    {
      "id": "sausage",
      "name": "ソーセージ",
      "tier": 1,
      "unit": "本",
      "stock": 200,
      "coefficient": 1.0,
      "last_counted": null
    },
    {
      "id": "bun",
      "name": "パン",
      "tier": 1,
      "unit": "個",
      "stock": 200,
      "coefficient": 1.0,
      "last_counted": null
    }
  ],
  "history": []
}
```

`history` には日付・商品・売上数を追記していく。

---

## 5. ツール（Strands の `@tool`）

以下の3つだけ実装する。**計算は必ず Python 側で行う。AI に数値計算をさせない。**

### `record_sales(date: str, product_id: str, quantity: int) -> str`

売上を記録し、レシピを掛けて在庫を減らす。

処理:
1. `products` からレシピを引く
2. 各 `item_id` について `消費量 = quantity × recipe.qty × coefficient`
3. 消費量を小数第1位で丸め、`stock` から引く
4. `history` に追記
5. 結果を文字列で返す（何を何個減らしたか）

### `record_count(item_id: str, actual_stock: float) -> str`

棚卸しの実測値を受け取り、係数を更新する。

処理:
1. 現在の `stock`（計算値）と `actual_stock`（実測値）を比較
2. 前回棚卸し以降の理論消費量を `history` から算出
3. 実際の消費量 = 前回実測値 − 今回実測値（初回は補正せず、実測値で `stock` を上書きするのみ）
4. `新係数 = 現係数 × (実際の消費量 ÷ 理論消費量)`
5. 新係数は **0.8〜1.5 の範囲にクリップ**する（異常値対策）
6. `stock` を `actual_stock` で上書き、`last_counted` を更新
7. 更新前後の係数を文字列で返す

### `get_stock_status() -> str`

全 Tier 1 品目の現状を返す。

返す内容: 品目名、現在庫、単位、係数、最終棚卸し日。

## 6. エージェントの役割

システムプロンプトで以下を指示する。

```
あなたはキッチンカーの在庫管理を手伝うアシスタントです。
店主は忙しいので、質問は最小限にしてください。

- 売上を伝えられたら record_sales を使って記録する
- 棚卸しの数を伝えられたら record_count を使う
- 在庫を聞かれたら get_stock_status を使う
- 数値の計算は必ずツールを使い、自分で暗算しない
- 係数が大きく動いたときは、数え間違いの可能性も店主に確認する
- 丁寧語で、簡潔に応答する
```

## 7. 動作確認（この通りに動けば完成）

```
$ python main.py

> 今日ホットドッグ40個売れました
  → ソーセージ 200 → 160本、パン 200 → 160個

> 在庫教えて
  → 一覧が返る

> ソーセージ数えたら152本でした
  → 係数が 1.0 から 1.05 に更新される
  → 在庫が 152 に上書きされる

> 今日は35個
  → 消費量に係数1.05が掛かって 36.8 → 37本減る
```
